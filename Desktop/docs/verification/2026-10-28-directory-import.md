# MultiMC 实例目录导入卡顿修复

用户给出的 `F:\Users\张桢锴\Documents\软件\MultiMC\instances` 是有效实例目录，包含 16 个可识别实例，不属于选错目录。

旧版真实复现：导入调用从日志 3.068 秒持续到 15.431 秒才返回，期间出现 85 次 `allInstances` 绑定循环。默认首个实例 `1.16` 的存档目录包含 3,798 个文件夹；隐藏的世界标签页也使用 Repeater 创建所有控件，造成明显主线程阻塞。

修复包括：

- 后台扫描目录并共享缓存，界面和启动器不再各自重复扫描。
- 只为选中的实例或明确的启动/设置操作创建 Prism 实例对象；列表阶段仅读取组件声明，不解析所有实例的依赖。
- 在组件信号触发前注册实例所有权和缓存，避免重入创建；界面按实例 ID/路径刷新资源，缓存显示状态，避免绑定循环。
- 后台读取模组、存档和截图信息；使用 QmlMaterial 虚拟列表和网格，只创建可见区域及少量缓存控件。隐藏的标签页不加载整个模型。
- CLI 快捷方式仍可在启动扫描完成前明确解析目标实例。
- 无效选择通过错误通知及实例目录页面说明原因，拒绝保存，保留现有列表。区分不存在、文件、单个实例、空目录及损坏 JSON；单个实例会提示其上一级目录。

## 回归

`Desktop/scripts/verify-directory-import.ps1` 使用原始目录只读验证首次导入和重启，检查 UI 心跳、实例数量、世界列表虚拟化、错误选择和 32 个原始配置文件的 SHA-256。所有程序数据、测试损坏配置及截图写入 `Desktop/.cache/import-checks/`，不读取原启动器账号文件，不启动游戏。

最终回归识别 16 个实例，首次导入约 51 毫秒；重启再次读取约 19 毫秒。3,798 个世界保留在数据模型中，滚动到列表末尾时仅创建 6 个行控件；非选中实例没有被全量初始化。主线程最大心跳间隔分别为 178 和 32 毫秒。错误选择不改变已导入列表，32 个原始配置文件的校验值保持不变。

完整机器检查结果见同名目录的 `pass-1.json`、`pass-2.json`；缓存中的截图可用于检查实际滚动和错误消息。另运行目录适配/实例库单元测试和桌面界面回归；符号链接提权测试保持禁用。未将“能导入”当作真实游戏启动验收。
