# 外部实例原地运行与启动资源检查 · 2026-10-29

本轮针对 `26.2_bac` 检查真实启动准备流程。外部实例不是导入副本：原游戏目录及其共享依赖直接参与运行，App 保存目录引用、适配配置和校验记录。

## 修正

- Prism/MultiMC 实例直接读取原实例的 `mmc-pack.json`、`patches/` 和启动器的 `meta/`，不把组件元数据或依赖库复制到 App。组件版本 JSON 已安装时无需额外存在 UID 列表索引。
- 类路径、依赖下载缓存、资源索引及资源对象指向原目录。缺失依赖和资源补到原目录。旧版虚拟资源重建、FML 依赖也使用原实例目录。
- 有效本地资源索引作为已安装快照使用，上游语言文件更新不再触发每次启动前重新获取索引。普通资源对象检查沿用 Prism 的存在性和大小判断；下载仍校验摘要。依赖库校验记录包含路径、修改时间、大小与预期摘要，未变更时跳过重复哈希。
- 原组件配置只在实际配置改变时保存，保留未知字段并先备份；刷新显示缓存不会重写原组件配置。清理 App 缓存不会删除外部依赖、资源或元数据。
- 使用 Prism 本机 Java 发现，保留原实例或原启动器的有效 Java 路径。不下载 JRE，不加入 Java 版本兼容性拦截步骤；Java 可执行文件有效性和架构检测仍保留。
- 自动下载源模式仍优先 BMCLAPI；镜像空闲超时缩短至 10 秒后按现有规则回退官方。国内源模式、官方源模式保留。
- Java 启动失败不再将整份进程环境输出到日志。
